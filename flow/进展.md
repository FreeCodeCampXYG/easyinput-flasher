## 2026-08-31 · main 基线与社区固件安全边界 · Codex
- 做了什么: 后端写入前增加受信 Release allow-list，拒绝未知/未审核 `repository@tag`；manifest 固定三段文件名与 `0x0/0x8000/0x10000` 偏移；新增发布规范和回归测试。
- 为什么这么做: 前端 `trusted` 可被 Wails 调用绕过，任意 manifest 偏移也会扩大写入范围；main 分支本身没有发布工作流，不能直接被烧录器安全消费。
- 怎么理解: “还原 main”应由 Maker `main` CI 生成带 manifest 的 `firmware-v-main-*` Release；社区功能先复用同一合同，不把编译器塞进桌面端。
- 产出(路径): `internal/application/app.go`、`internal/application/app_test.go`、`internal/firmware/manifest.go`、`internal/firmware/manifest_test.go`、`docs/FIRMWARE_PUBLISHING.md`、`README.md`、`DEV_STATE.md`。
- 问题 → 怎么解决: 新 application 测试在本机 Windows 执行阶段被 `application.test.exe: Access is denied` 拦截；已确认 `go test -c` 可编译，待 CI/允许执行测试环境重跑。
- 下一步(交接棒): 在 `easy-input-maker/main` 合入发布 workflow/manifest 脚本并创建绑定 main SHA 的官方 Release，再用新烧录器验证下载、写入和 HID 恢复。
