## 2026-08-31 · ESP32-S3 的 chip-id 被误当成通用验身命令   [已解决]
- **现象**: 下载模式 COM 端口已连接，界面“读取信息”却显示 `烧录工具执行失败: exit status 2`。
- **根因**: ESP32-S3 没有可用的 `chip-id`；工具提示后会回退读取 MAC，但命令仍以非零退出。发布 helper 还缺少 stub 数据，普通模式下进一步放大了该错误。
- **解决**: 不再调用 `chip-id`，改用 ROM 兼容的 `--no-stub read-mac` 与 `flash-id`；工具失败保留脱敏且限长的诊断文本。
- **教训 / 怎么避免**: 芯片族命令不能按 ESP32 通用示例套用；必须针对目标 S3 用真实下载端口做只读命令级验证，再调整状态机。

## 2026-08-30 · 初始 Vite 版本存在开发服务器安全告警   [已解决]
- **现象**: `npm audit` 报告 Vite 6.0.7 与其 esbuild 链存在 Windows 路径读取相关告警。
- **根因**: 初始前端模板锁定版本落在已披露问题范围内。
- **解决**: 最小升级到兼容的 `vite 6.4.3`，重建 lockfile 后 `npm audit` 为 0 漏洞，类型检查和生产构建通过。
- **教训 / 怎么避免**: 新增桌面前端依赖必须先锁定版本并运行 audit；不执行无审查的 `npm audit fix --force`。

## 2026-08-30 · Linux runner 缺少 Wails WebKitGTK 4.0   [待验证]
- **现象**: 六平台 CI 的 Linux x64/ARM64 在 Wails 编译阶段找不到 `webkit2gtk-4.0.pc`；Windows 和 macOS job 已通过。
- **根因**: workflow 只安装 `libwebkit2gtk-4.1-dev`，而 Wails v2 当前 Linux 构建链仍按 4.0 pkg-config 名称链接。
- **解决**: CI/Release 改为同时安装 `libwebkit2gtk-4.0-dev` 与 4.1；待下一次 CI 确认 Ubuntu runner 的 4.0 包可用。
- **教训 / 怎么避免**: Wails Linux 原生构建必须按实际 pkg-config 错误安装对应开发包，不能只依据发行版文档中的运行时版本命名。
